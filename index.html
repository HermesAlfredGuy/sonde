07 — questions

The ones data teams ask first.

Which systems does Sonde connect to?

Postgres and Timescale directly; Snowflake, Oracle, SQL Server and BigQuery through the warehouse adapter; and PI, Ignition and CygNet through the historian connector, which reads tags as a normalised table. A CSV or Parquet drop works for one off assets.

Can it change production data?

Only through the gate, and only after a named approver signs the diff. The account used for investigation has no write grant at all; writes run through a separate, scoped account created when you approve.

How do you know the SQL is correct?

Four checks run before a result is shown: the query parses in the target dialect, a dry run returns a plan under the cost ceiling, row counts agree with the source tables, and the invariants you define hold. Oil plus water equals total fluids, for example. A failed check is reported as a failed check, never as a plausible number.

What happens when it is wrong?

Every run keeps its query and row counts, so a wrong answer is traceable rather than mysterious. Mark a run as wrong from the result view and the corrected query becomes the reference for that question next time.

Does our data leave the network?

No. The agent runs in your VPC or on prem. Model calls carry the schema, the question and the query text, never the row data, unless you enable row context for a specific run.

Which model does it use?

A hosted frontier model by default, or your own endpoint if you run one. The planner and the SQL writer are separate calls, so you can pin the writer to a model you have approved.

How is usage metered?

Rows scanned per asset per day, not tokens or seats. A refused query is not charged. Historic results are metered again only when they are re run against fresh data.

What does a pilot look like?

One asset, read only, six weeks. We index the estate with your data team, run the nightly sweep, and hand over the audit log at the end. If the numbers do not hold up, the log is yours to keep.
