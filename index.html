Reads on a replica. Writes through a gate.

The agent is useful because it can act. It is safe to run because it cannot act alone: every write is a single statement, dry run first, signed off by a person whose name lands in the log.

  • Replica access only. Row data stays put unless you opt in per run.
  • Approver must be a named person in your organisation. Sonde cannot approve for them.
  • Every write ships with a rollback statement.
  • Run log kept 90 days, exportable as SQL or CSV.
  • Runs inside your VPC or on hardware you own.

The ones data teams ask first

Does Sonde read row data?

No. It reads schema, column types and counts. Row context is opt in for a single run, and the run log says when it was used.

Which databases does it connect to?

Postgres, SQL Server, Oracle, Snowflake and Timescale, connected to a replica rather than the primary.

Can it change production data?

Only through the gate, one approved statement at a time. The statement is dry run first and every write carries its rollback.

Who approves a write?

A named person in your organisation with the approver role. Sonde cannot approve on their behalf, and the gate cannot be switched off.

How long does setup take?

Replica credentials and a schema read, usually inside one day. The first question usually runs the same afternoon.

Where does the SQL go?

Into the run log, kept 90 days, exportable as SQL or CSV. Nothing is used to train a shared model.

Does it run on our own servers?

Yes. Inside your VPC or on hardware you own, with outbound access limited to the model endpoint you approve.

What does the pilot cost?

Nothing for six weeks. After that it is priced per asset, not per seat, and the price is fixed for the first year.
