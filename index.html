What changes

Answers you can defend
in a meeting.

The point is not that a model can write SQL. It is that the number arrives with its provenance, the write waits for a person, and the schema you already have is enough.

01

Every answer arrives with its receipts

The SQL, the tables it read, the row count and the runtime stay with the answer, so a number can be checked instead of trusted.

02

Writes stop at a person

The agent cannot approve itself. The gate keeps the statement, the affected rows and the rollback, with a name on it.

03

Your schema, not a migration

Historian, SCADA tags, allocations and decline models stay where they are. Nothing has to be reshaped before it can be asked anything.

04

A cost ceiling before the read

Every question is dry run under a limit you set, on a replica, so a broad question cannot become a production incident.

Questions

Before you ask.

Eight answers, including the ones a concept page usually avoids.

Is Sonde a real product?

No. This is a concept study: an art-directed argument for how a production data agent should behave. There is no backend on this page, nothing is for sale, and there is no company behind it.

Is the demo real?

The interaction is real. Click a question and the panel types, writes and closes a gate. The answers are scripted from a synthetic dataset of three fictional wells, and the panel says so on its face.

Does it read row data?

In the concept, no: schema, column types and counts only. Row context is opt-in for a single run, switched on by a named person, and it expires with the run.

Which systems would it connect to?

Postgres, SQL Server, Oracle, Snowflake and Timescale, always through a replica. The historian and the SCADA tag database stay read-only in the design.

Can it change production data?

Only one approved statement at a time, through the gate, with the rollback attached before the approve button exists. Anything wider is out of scope by design.

Who approves a write?

A named person with the approver role, inside your organisation. The agent cannot approve for them, and the approval is stored with the statement rather than in a log beside it.

Where does the SQL go?

Into a run log with the question, the plan, the row count and the approver. Exportable as SQL or CSV, so an answer can be rebuilt outside the tool.

What does it cost?

Nothing. Nothing is being sold. If you want the argument, it is on this page; if you want the artwork or the code, it is in the repository.
